## Context

Range Support Tool 2 helps operators verify site mappings, inspect tracking data and troubleshoot unusual radar-tracking errors. It is an existing, team-built application; I contribute selected features and maintain its macOS delivery and beta release automation.

## My contributions

- **macOS delivery:** application and DMG packaging, Developer ID signing, notarization and ticket stapling.
- **Beta release automation:** maintain the CI/CD pipeline, including platform selection, version stamping and release channels in Azure Pipelines.
- **Radar controls:** implement radar API controls, including adjustment of the radar's onboard camera exposure.
- **Companion workflows:** launch integration and data handoff for Sim Studio and Range Studio.
- **Selected integrations:** survey-source archiving and cloud-backed update/distribution services.

## Design decisions

A release is a coordinated set of artifacts. The desktop application, its companion tools and the update service need consistent platform and version information.

For macOS, distribution also means handling nested code, signing and notarization as part of the release process. These details matter when an operator copies an application out of its installer and uses it later.

## Project overview

Range Support Tool 2 is an existing shared application. My work is a contribution and maintenance story: keeping the macOS release usable while extending specific operator-facing features and improving how related tools are delivered.

The release pipeline supports bundled companion applications, and the distribution work includes a download portal and update lookup. Survey-file archiving preserves source data and metadata through a presigned upload flow.

This project shows the connection between application development and operational ownership. Packaging, compatibility, user feedback and integration work continue after a feature is written. The broader calibration and support product remains a team-built system.
